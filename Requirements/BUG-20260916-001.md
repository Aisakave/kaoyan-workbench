# [BUG] 批量导入取消选择后页面残留「选择文件/未选择文件」原生控件

> 编号：BUG-20260916-001-残留文件选择控件
> 关联：REQ-20260915-013（批量导入引入，用户发现）
> 状态：已修复
> 创建：2026-09-16
> 更新：2026-09-16

## 现象描述

手机端与电脑端向下滚动到页面底部，会出现原生的「选择文件 / 未选择文件」控件（浏览器默认 file input 渲染），与深色主题风格冲突，影响美观。截图确认：底部出现两个并排的原生 file input。

## 复现步骤

1. 打开任意页面，点击「批量导入」→ 引导弹窗 →「选择文件夹开始」
2. 在弹出的文件选择对话框中**取消**（不选文件）
3. 向下滚动到页面底部：出现「选择文件 / 未选择文件」控件；重复操作会累积多个

## 影响范围

仅视觉残留，无数据影响；累积的隐藏节点在刷新后消失。

## 根因分析

`js/ui.js` 的 `pickFiles()` 把动态创建的 `<input type="file">` `appendChild` 到 `document.body` 但**未隐藏**，且只在用户**选中文件**（触发 `onchange`）后才 `input.remove()`。用户取消文件对话框时 `onchange` 不触发 → input 残留在 body 末尾，浏览器默认渲染出「选择文件 / 未选择文件」。多次取消累积多个。

对照：页面静态的「导入备份」input（`index.html` `#fileImport`）带 `style="display:none"`，无此问题；`pickImages()` 不 append 到 DOM，也无此问题。

## 修复方案

`js/ui.js` `pickFiles()` 两处加固：

- 创建后立即 `input.style.display = 'none'`（即使残留也不可见）
- 监听 `cancel` 事件（取消对话框时触发）→ `input.remove()` 及时清理

## 验证结果

- `node --check` 语法通过。
- 本地 8123 浏览器实测：点「批量导入」→「选择文件夹开始」后，`document.querySelectorAll('input[type=file]')` 全部 `hidden: true`（静态导入备份 input + 动态 input 均不可见），页面不再显示原生控件。
- 选中文件路径（`onchange` → remove）逻辑未改动，此前 REQ-013 已实测通过。
