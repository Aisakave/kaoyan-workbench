# REQ-20260922-001 万题量级加固（导入导出与存储风险汇总）

状态：**部分落地**（I-12 + I-01/02/03 已实现并提交，见 `Requirements/REQ-20260922-002.md`；I-04/05/06/08/09 延后到几千题量级后再做，I-07 不修复，I-11 为运维约定）

## 背景

- 用户当前 100 道错题、备份文件 124.8MB（`.jsonl` v2 流式格式）。目标量级为**上万道错题**。
- REQ-20260921-001（流式备份）与 REQ-20260921-002（结构化数据迁 IndexedDB）解决了**内存上限**与**localStorage 配额**两道硬墙，选型方向正确。
- 但两者均未覆盖：导入的原子性、导入前的配额预检、state 的写入放大、IndexedDB 连接开销、缩略图重建成本。
- 本轮为**纯诊断**，未改动任何业务代码。所有规模数字均由**真实备份文件 `backup-2026-09-22.jsonl` 实测校准**，非纯估算。

## 真实基线（`backup-2026-09-22.jsonl` 实测）

| 指标 | 真实值 |
|---|---|
| 备份文件 | 124.80 MiB（130,860,651 字节） |
| 错题数 | 100 题，其中 99 题含图 |
| **图片张数** | **242 张（2.42 图/题）** |
| 图片行体积 | 平均 527.9 KB / 最小 14.3 KB / **最大 12.36 MiB** |
| 原图二进制 | 93.56 MiB（396 KB/张） |
| state 体积 | **39.7 KB**（378 B/题；`wrongQuestions` 36.9 KB / 100 条） |
| meta 行体积 | 0.039 MiB |

关键发现：**单张图片体积跨越约 900 倍**（14.3 KB ~ 12.36 MiB）。平均 396 KB 不代表实际负载，进度与耗时由最大的几张决定。

### 实测基准

两个新增脚本（Node 22，与 Edge 同代 V8）：
`.tools/bench-backup-cpu.js`（等价复现源码实现）、`.tools/bench-real-scale.js`（按真实 state 形状与图片分布测量）。

| 操作 | 实测 | 说明 |
|---|---|---|
| `JSON.stringify`(万题 state 3.40MB) | **12.6 ms** | I-04 每次改数据都付 |
| `structuredClone`(万题 state 3.40MB) | **23.9 ms** | I-04 每次改数据都付 |
| → **`Store.save` 单次合计** | **≈36 ms** | 100 题时仅 **0.39 ms**（stringify 0.12 + clone 0.27） |
| `JSON.parse`(万题 state) | 11.0 ms | 导入末段一次 |
| `JSON.parse`(最大图行 12.36 MiB) | 9.3 ms | 单张 |
| `dataURLToBlob`(最大图) | 17.9 ms | 单张，未含 `createImageBitmap` 解码 |
| 单图链路 CPU（按 528KB 均值折算） | 导出 ≈1.24 ms / 导入 ≈1.22 ms | CPU 不是主要瓶颈 |

**原「meta 行是 O(N) 内存风险」的判断已被实测否定**：万题 state 仅 3.40 MB，meta 行序列化/解析成本可忽略。REQ-20260921-001 的「内存恒定」结论成立。

### 配额与浏览器矩阵

| 浏览器 | IDB 配额上限 | 万题（需 ≈9.6GB）是否可行 |
|---|---|---|
| **Edge / Chrome 桌面** | 同源池约为磁盘可用空间的 60% | 需所在盘**剩余 ≥16GB**；满足则可 |
| Firefox | 默认 best-effort 约为磁盘 10% | **不可行**，约 2,000 题即封顶 |
| Safari | 约 1GB（或请求后更高） | **不可行** |

`navigator.storage.persist()` 为 best-effort 申请，无弹窗，浏览器自行决定是否批准；需在设置弹窗确认 `persisted()` 是否为 true。

## 残余运维风险（I-11 展开）

放弃云同步后，**备份文件是唯一副本**，其安全性完全由「备份落盘位置」决定。

| 场景 | 风险 | 缓解建议 |
|---|---|---|
| Edge 配置目录与 D 盘在**同一块物理硬盘** | 硬盘故障 → 应用数据与备份同时丢失 | 备份另存一块物理盘 / U 盘 / 移动硬盘 |
| 备份在 D 盘、配置在另一块盘 | 具备盘级冗余 | 保持即可 |
| 误删 / 勒索软件 / 手滑覆盖 | 无异地副本可回退 | 保留最近 2–3 份（按日期命名已可区分） |
| 单份备份 12.2GB × 多版本 | D 盘空间被快速吃满 | 约定保留份数与轮换规则 |
| 重装系统 / 换机 | 备份文件若未随盘迁移则丢失 | 备份目录固定并纳入个人文件迁移清单 |

**需用户自行确认**（本轮因本机安全策略限制，系统级工具被禁用，未能读取磁盘拓扑）：D 盘与 Edge 配置所在盘是否为同一块物理硬盘。确认方式：任务管理器 → 性能 → 逐个查看磁盘，或「磁盘管理」中查看分区归属的磁盘编号。

## 暂定验收标准（待 D-1 确认后细化）

1. 导入前若可用配额不足，**在写入任何图片之前**即中止，并给出明确原因文案（非「文件格式不正确」）。
2. 导入过程中失败（人为注入单张异常 / 配额不足），已写入的图片被回滚，IndexedDB 回到导入前状态。
3. 万题量级（10,000 题 / ≈24,200 张图 / 12.2GB 备份）模拟数据下，导入 → 导出 → 再导入全链路完成，无内存溢出、无标签页崩溃。
4. 导入结束比对 `restored` 与 `meta.imagesTotal`，不一致时有明确告警。
5. 单次数据变更（勾选复习 / 记录学习时长）的主线程阻塞在万题量级下不超过约定阈值。
6. 导出图片与库内原图**逐字节一致**（沿用 REQ-20260921-001 标准，回归不降级）。
7. 仓库中不再出现任何备份文件为未跟踪状态。
