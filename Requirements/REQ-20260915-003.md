## 分类与状态

- 分类：功能优化

## 一、需求背景

复习功能上线后用户反馈：某道题每次复习都点「✅ 做对了」，却仍显示在「未掌握」筛选里，与「复习做对 = 掌握」的直觉冲突。

根因：掌握度筛选原口径只按 `recurCount`（做错次数）划分——「未掌握」= 从未做错（`recurCount = 0`）；复习做对只累加 `reviewCount`（成功复习次数），不改变分类。两者语义不一致导致困惑。

## 二、目标

- 复习连续做对 3 次 → 自动判定「已掌握」，从「未掌握」移出
- 「已掌握」成为独立筛选档位（全部 / 未掌握 / 复发中 / 已掌握 / 永久保留）
- 任何一次「又做错」（复习弹窗点错 或 「再错 +1」）都打断连续做对

## 三、方案（用户已确认：连续做对 3 次算已掌握）

| 档位 | 判定口径 |
|---|---|
| 已掌握 | 非永久保留 且 `reviewCount ≥ 3`（连续做对 3 次；做错即归零） |
| 未掌握 | 非永久保留 且 `reviewCount < 3` 且 `recurCount = 0` |
| 复发中 | 非永久保留 且 `reviewCount < 3` 且 `recurCount ≥ 1` |
| 永久保留 | `permanent = true`（`recurCount ≥ 3`） |

要点：

- 四档互斥且全覆盖；「已掌握」优先于「复发中」（做错过、但最近连续做对 3 次 → 已掌握）。
- 配套：`bumpWrong`（再错 +1）同步清零 `reviewCount`，与复习弹窗「又做错了」行为一致，保证「已掌握 = 连续做对」语义成立。
- 纯派生状态，无新增持久化字段、无数据迁移。
- 已掌握的题到期后仍正常进入「待复习」队列（已掌握 ≠ 不用复习）。

## 四、验收标准（行为验收矩阵）

| 场景 | 前置条件 | 操作 | 预期结果 | 验证状态 |
|---|---|---|---|---|
| 判定已掌握 | `reviewCount = 2` 的题 | 复习 → 做对了 | `reviewCount = 3`，进入「已掌握」档 | ✅ Node 断言 + 实测 |
| 未掌握不含已掌握题 | 有 `reviewCount ≥ 3` 的题 | 点「未掌握」筛选 | 不显示（本次修复核心） | ✅ 实测 |
| 已掌握独立筛选 | 有已掌握题 | 点「已掌握」筛选 | 只显示已掌握题，卡片带绿色「✅ 已掌握」标签 | ✅ 实测 |
| 四档互斥 | 混合状态数据 | 逐档查看 | 每题恰好属于一档 | ✅ Node 断言（8 样本） |
| 再错打断已掌握 | 已掌握题 | 点「🔁 再错 +1」 | `reviewCount` 归零、`recurCount + 1`，移出「已掌握」 | ✅ Node 断言 |
| 复习做错打断 | 已掌握题 | 复习 → 又做错了 | `reviewCount` 归零，移出「已掌握」 | ✅ 断言（既有逻辑） |
