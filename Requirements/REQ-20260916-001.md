# 需求 REQ-20260916-001 批量导入支持一题多解析图（题号优先 + 时序兜底）

> 分类：功能优化 · 影响范围：js/views/wrongBook.js
> 状态：待用户实测 · 最后更新：2026-09-16
> 关联：REQ-20260915-013（批量导入基础功能）、REQ-20260915-014（批量导入增强）、REQ-20260916-005（提示文案统一命名口径）

## 一、背景与目标

用户反馈部分错题「一张解析图不够，需要配两种解析图」（如一张解析含不同解法/易错点）。现有批量导入按**文件修改时间两两配对**（题目+答案=1 条），隐含前提是「一题固定 2 张图」。当一题有 3 张图（题目+解析一+解析二）时，时序法会把 3 张硬凑成「题目+解析一」一条再「解析二」单独成条，配对错乱。

**目标**：支持一题多图（题目 + 多张解析），同时不影响既有「按时序两两配对」的用法与已导入数据。

## 二、口径（用户已确认）

用户选定「题号优先 + 时序兜底」方案（实现注记见 4.1）：

| 决策点 | 结论 |
|---|---|
| 思路 | 从文件名提取「题号」的图按题号分组为一题；无题号或题号唯一时回退现有两两配对 |
| 题号判定 | 文件名主名（去扩展名）匹配 `/(题\d+\|T\d+)/i` 提取题号（如 `题1`、`T2`）；**仅当某题号出现 ≥2 张图时才启用分组**（单张不误判） |
| 组内定为题/解析 | 组内按文件时间升序，**第一张当题目，其余当解析**（一题可含 1 题目 + N 解析） |
| 时序兜底 | 题号唯一或无数情形，退回「按文件时间两两配对」原逻辑 |
| 旧数据兼容 | 现有 UUID 文件名（无题号）不触发分组，行为不变；已导入数据不受影响 |
| 数据影响 | 无新增字段；images 数组本已支持多图；仅新增不覆盖 |
| 命名口径 | 用户命名须用「题N」（题+数字，如 `题1`），「题目1」不识别；提示文案已按 REQ-20260916-005 统一 |

## 三、命名规则（给用户）

同一道错题的图片在文件名末尾用**同一个题号 + 角色**命名，例：

| 图片内容 | 建议文件名 |
|---|---|
| 题目 | `题1-1`、`题1-题目` |
| 解析一 | `题1-2`、`题1-解析1` |
| 解析二 | `题1-3`、`题1-解析2` |

规则要点：
- 题号 = 文件名中的「题+数字」（如 `题1`）或「T+数字」（如 `T2`），写在文件名末尾，如 `微信图片_20260915132316_211_1题1-题目.png`；
- 注意是「题1」（题字后直接跟数字），「题目1」不会被识别；
- 不同题用不同题号（`题1`、`题2`、`题3`…）；
- 一组内第一张（按文件时间）会被当作题目，其余当解析；
- 不需要多图时，什么都不用改，照旧「题目→解析」两张相邻粘贴走时序配对即可。

## 四、技术方案

### 4.1 分组逻辑（`groupByQmark`，实际实现）

```
files 按 fileTime 升序（优先文件名时间戳，如 微信图片_20260915132316_xxx；回退文件系统时间）
qmark(f)  = 主名(去扩展名) 匹配 /(题\d+|T\d+)/i 提取题号；无 → null
counts    = 各题号出现次数
pairs = []
for 每张图：
  有题号 且 counts[题号] ≥ 2 且 未分组 → 取同题号所有图成一组(按 fileTime 升序) → 组=pairs 一条
  否则 → 纳入「时序孤图」集合
时序兜底：孤图按 fileTime 升序两两配对（题目+解析）；单数尾图单独成条
```

> 实现注记：初版按「文件名第一个 `-`/`_` 前的前缀」设计，实测微信另存为文件名（`微信图片_…`）前缀全部相同会把所有图误合并为一题，实现时改为「题号分组」（`qmark` + `groupByQmark`，识别 `题\d+`/`T\d+`），本文档已按实际实现同步。

组内第一张=题目，其余=解析；`runBulkImport` 现有逻辑已按 `imgs[0]` 取时间、按 `imgs` 全部写入，无需改动。

### 4.2 预览文案

- 条目 chip 标注：单图「单图」、2 图「题+答」、>2 图「N 张图」区分多图条。
