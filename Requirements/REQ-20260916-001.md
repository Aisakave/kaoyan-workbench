# 需求 REQ-20260916-001 批量导入支持一题多解析图（前缀优先 + 时序兜底）

> 分类：功能优化 · 影响范围：js/views/wrongBook.js
> 状态：待用户实测 · 最后更新：2026-09-16
> 关联：REQ-20260915-013（批量导入基础功能）、REQ-20260915-014（批量导入增强）

## 一、背景与目标

用户反馈部分错题「一张解析图不够，需要配两种解析图」（如一张解析含不同解法/易错点）。现有批量导入按**文件修改时间两两配对**（题目+答案=1 条），隐含前提是「一题固定 2 张图」。当一题有 3 张图（题目+解析一+解析二）时，时序法会把 3 张硬凑成「题目+解析一」一条再「解析二」单独成条，配对错乱。

**目标**：支持一题多图（题目 + 多张解析），同时不影响既有「按时序两两配对」的用法与已导入数据。

## 二、口径（用户已确认）

用户选定「前缀优先 + 时序兜底」方案：

| 决策点 | 结论 |
|---|---|
| 思路 | 有「共同前缀」的图按前缀分组为一题；无共同前缀的回退现有两两配对 |
| 前缀判定 | 文件名主名（去扩展名）取第一个 `-` 或 `_` 前的部分作为前缀；**仅当某前缀出现 ≥2 张图时才启用分组**（单张不误判） |
| 组内定为题/解析 | 组内按修改时间升序，**第一张当题目，其余当解析**（一题可含 1 题目 + N 解析） |
| 时序兜底 | 前缀唯一或无数情形，退回「按修改时间两两配对」原逻辑 |
| 旧数据兼容 | 现有 UUID 文件名（前缀唯一）不触发分组，行为不变；已导入数据不受影响 |
| 数据影响 | 无新增字段；images 数组本已支持多图；仅新增不覆盖 |

## 三、命名规则（给用户）

同一道错题的图片用**同一个前缀 + 序号**命名，例：

| 图片内容 | 建议文件名 |
|---|---|
| 题目 | `题1-1`、`题1-题目` |
| 解析一 | `题1-2`、`题1-解析1` |
| 解析二 | `题1-3`、`题1-解析2` |

规则要点：
- 前缀 = 第一个 `-`（或 `_`）前的文字，如 `题1`；
- 不同题用不同前缀（`题1`、`题2`、`题3`…）；
- 一组内第一张（按修改时间）会被当作题目，其余当解析；
- 不需要多图时，什么都不用改，照旧「题目→解析」两张相邻粘贴走时序配对即可。

## 四、技术方案

### 4.1 分组逻辑（替换 `pickBulkFolder` 的循环）

```
files 按 lastModified 升序
prefixOf(f) = 主名第一个 '-'/'_' 前的部分；无分隔符 → null
counts     = 各非空前缀出现次数
pairs = []
for 每张图：
  有非空前缀 且 counts[prefix] ≥ 2 且 未分组 → 取同前缀所有图成一组(按时间序) → 组=pairs 一条
  否则 → 纳入「时序孤图」集合
时序兜底：孤图按时间序两两配对（题目+解析）；单数尾图单独成条
```

组内第一张=题目，其余=解析；`runBulkImport` 现有逻辑已按 `imgs[0]` 取时间、按 `imgs` 全部写入，无需改动。

### 4.2 预览文案

- 顶部说明由「已按修改时间两两配对」改为「已按前缀分组/修改时间配对」动态文案；
- 有前缀分组的条目，chip 标注显示「题+答×N」区分多图条。
