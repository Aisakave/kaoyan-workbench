# REQ-20260916-002 复习队列防堆积（每日限量 + 逾期智缓）

## 一、背景与目标

错题簿复习采用递增间隔 3→5→7→10→14→21→30 天。用户反馈两点真实痛点：

1. **到期堆积**：题量变大后，同一天会有很多题同时到期（尤其中 30 天档齐到期），待复习一次性列出全部，单日负担过重。
2. **逾期催办**：长期没复习的题 overdue 一直涨，永远排在队列最前催办，哪怕用户其实早已掌握。

本次目标：在**不改变复习间隔数据**、**不丢任何复习任务**的前提下，让「每日实际要做的题量」保持可承受、可流动，让真正生疏的题永远排在前面。

## 二、需求口径

| 项 | 决策 |
|---|---|
| 每日限量 | 待复习列表最多显示前 N 道；超出部分计入「顺延"，明日优先补位，**不丢不漏** |
| 默认上限 | 自适应：取近 14 天到期题量中位数，下限 5、上限留空即不限；可在设置页覆盖 |
| 逾期智缓 | 判定「稳定掌握」的题不再天天催，从每日队列淡出；**但做错立即回归队列置顶** |
| 稳定性判定 | 同时满足：① 达到 30 天档（reviewCount>=6）② 最近连续 2 次都对 ③ 逾期 <= 7 天 ④ 非 permanent 永久保留 |
| 被智缓的题 | 仍在「全部」tab 可随时找；待复习处于「收纳区」不影响计数；仅当前队列淡出 |
| 设置入口 | 设置页新增「每日复习受理上限（道/天，0=不限，空=自适应）」 |
| 数据影响 | 新增 `settings.dailyReviewCap`（默认 0=不限），migrate 自动兜底，零迁移、可回滚 |

## 三、技术方案

### 3.1 数据层（store.js）
- `defaultData().settings` 新增 `dailyReviewCap: 0`（0=不限）。
- `migrate()` 用现有 `Object.assign(defaultData().settings, data.settings)` 自动补默认，无需版本分支。

### 3.2 稳定性判定（utils.js 新增派生函数）
新函数 `isStabilized(w, intervalBase)`，判据全由既有字段派生，**不新增字段**：

```js
function isStabilized(w, b){
  if (!w || w.permanent) return false;
  if (w.reviewCount < 6) return false;        // 未达30天档
  const hist = (w.reviewHistory || []).slice(-2);
  if (hist.length !== 2 || hist.some(h => !h.correct)) return false; // 非连续2对
  const meta = reviewMeta(w, b);
  return meta.overdueDays <= 7;               // 逾期<=7天才可信
}
```

### 3.3 智能队列（controller.js 重写 `reviewDueList`）
按以下步骤产出，返回 `{ active, deferred, stabilized }`：

1. 收集所有 `due <= now` 的项（含逾期与今日到期）。
2. 分拣：`isStabilized` 的进 `stabilized`（收纳区，不进每日队列）→ 排除。
3. 剩余按「优先级」排序：**逾期天数大者优先** → 同逾期按到期早优先（原 due 升序做次级）。
4. 限量：`active = 剩余取前 N`；`deferred = 超出部分`（顺延，明日优先补位）。
   - N = 0（未设）→ 不限；N 为空/自适应 → 取近14天到期数中位数 clamp[5,∞]；N>0 → 固定。
5. 返回三类，供 UI 区分渲染。

说明：`reviewDueCount`（侧栏红点）沿用全部到期 `due<=now` 数，**不受限量影响**，红点始终反映真实待办。

### 3.4 UI（wrongBook.js renderReviewTab + dashboard.js 设置）
- 待复习 Tab 顶部：`共 N 题到期 · 今日受理 X · 顺延 Y · 稳定收纳 Z`，简明可读。
- 活动区渲染 `active`（可复习）；`deferred` 折叠提示「另有 Y 道已顺延，明日优先」；`stabilized` 折叠区「N 道已稳定掌握，暂不催办（做错即回归）」。
- 设置页在 `dailyReviewGoal` 附近新增 `dailyReviewCap` 数字输入。

### 3.5 做错回归
`isStabilized` 实时计算：一旦稳定题再次做错 → `reviewCount` 重置、`recurCount+1` → 不再满足判据 → 自动回到每日队列。无需额外状态。

## 四、验收标准（DoD）
1. 到期题超过上限时，待复习只显示前 N，其余计入顺延且次日仍在。
2. 逾期久的题排在当日到期前面。
3. 稳定掌握题（30档+连续2对+逾期<=7+非永久）不出现在每日队列，但在全部 tab 可查。
4. 稳定题做错后立即回归队列。
5. 设置页可设上限；0=不限、空=自适应。
6. 侧栏红点始终 = 全部到期数，不受限量影响。
7. node 语法检查全过；构造堆积数据实测各场景；console 零报错。

## 五、范围与不做项
- 不做：改变复习间隔序列、永久保留弹窗逻辑、增加新存储字段（除 settings 一个键）。
- 不改既有已入库数据；旧备份导入无损。

## 六、风险与回滚
- 低。仅新增 settings 默认键 + 改写 `reviewDueList`。回滚：删掉 `dailyReviewCap` 逻辑即恢复原全部展示。
