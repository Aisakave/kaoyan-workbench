# REQ-20260915-006 · 错题复习「基础间隔」可配置

> 日期：2026-09-15
> 分类：功能优化
> 状态：已确认，已完成
> 功能进度：`Progress/PROG-REQ-20260915-006.md`

## 1. 背景与目标

错题复习采用渐变间隔（3→5→7→10→14→21→30 天），新错题起步要到 3 天后才进入「待复习」队列，用户无法当天验证复习闭环是否正常；同时希望间隔能贴合个人备考节奏。故计划将复习的**首档（基础）间隔**改为可配置。

## 2. 确认口径

- 方案：用户选定「**只调基础间隔**」——
  - 新增 `settings.reviewBaseInterval`（默认 3，合法范围 0~5），语义 = **新题首次到期 / 做错清零后再到期**回到的天数。
  - 做对后仍按固定序列 `5→7→10→14→21→30` 递增，保持科学复习曲线。
  - 填 `0`：新收录错题**立即**进入「待复习」，便于快速验证；填 `1` 则次日。
- 不做：整套间隔序列自定义、修改已有复习算法。
- 入口：首页「目标设置」弹窗新增一项「错题复习基础间隔（天，0=收录后立即到期）」。

## 3. 数据设计（已确认）

### 3.1 变更

| 位置 | 字段 | 类型/默认 | 说明 |
|---|---|---|---|
| `settings` | `reviewBaseInterval` | `number`，默认 `3`，范围 `0~5` | 错题首档复习间隔；0=收录即到期 |

### 3.2 迁移与备份

- `Store.migrate()` 经 `Object.assign(defaultData().settings, data.settings)` **自动回填**默认值 3，旧数据零迁移成本、无需备份、无需回滚。
- 导出为整包 dump 自动含新字段；导入走 `Store.migrate` 无损补齐。`CURRENT_VERSION` 不升。

## 4. 功能规格

- `nextReviewInterval(reviewCount, base)`：`reviewCount=0` → `clamp(base, 0, 5)`；`reviewCount≥1` → `REVIEW_INTERVALS[reviewCount]`（即 `[5,7,10,14,21,30]` 递增，封顶 30）。
- 到期计算透传：`reviewDue(w, intervalBase)` / `reviewMeta(w, intervalBase)` 增可选参数；`Controller.reviewDueList()` 从 `state.settings` 读取并传入。
- 视图层（`wrongBook.js`）：以 `Controller.getSettings().reviewBaseInterval` 统一展示「首次到期文案 / 下次间隔 / 做错提示」，不再硬编码 3 天。
- 设置弹窗（`dashboard.js`）保存时对输入 `clamp` 0–5，留空回退 3。

## 5. 验收矩阵

| # | 项目 | 通过标准 |
|---|---|---|
| 1 | 设置生效 | 「目标设置」新增基础间隔项，默认 3 |
| 2 | 快速验证 | 设为 0 后，新收录错题立即出现在「待复习」 |
| 3 | 间隔递增 | 对已入队错题复习「做对了」后，下次间隔进入下一档（5 天） |
| 4 | 边界约束 | 输入被收敛到 0~5；留空回退 3 |
| 5 | 默认兼容 | 未改动 settings 时默认仍为 3，原备考节奏不变 |

## 6. 验证证据

- `node --check` 5 个改动文件语法全部通过。
- 浏览器端到端实测 7 步全 PASS：首页加载 → 待复习空态（默认 3 文案）→ 设置弹窗新增项默认 3 → 改为 0 保存 → 新增错题 → 「待复习」立即出现 1 条 → 复习「做对了」后显示「上次复习 0 天前 · 剩 5 天到期」。

## 7. 风险评估与回退

- 风险低：新字段有默认值且 `migrate` 兜底；仅改视图展示与到期透传，不动存储结构。
- 回退：删除 `reviewBaseInterval` 相关字段与代码即还原默认 3 行为；`reviewCount/lastReviewedAt/recurCount` 不影响。
