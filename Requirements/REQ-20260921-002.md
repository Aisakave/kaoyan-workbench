# REQ-20260921-002 存储层加固：结构化数据迁 IndexedDB + 持久化申请

## 背景（现状与依赖）

- 结构化数据（settings/tasks/wrongQuestions/materials 等全部文字数据）存于 `localStorage`，图片存于 IndexedDB（`kylc-images` 库 `images` store）。
- `localStorage` 浏览器配额约 5~10MB：按每道错题 0.5~2.5KB（含 reviewHistory 上限 30 条）估算，**约 4,000~10,000 道错题将写满**，且失败方式隐蔽（`save()` 返回 false + toast，界面改动看似成功，刷新后丢失）。用户目标量级为几千道题（2 万张图片 ≈ 8,000 题），必然撞墙。
- IndexedDB 未申请 `navigator.storage.persist()`：数据量大时磁盘紧张下存在被浏览器回收清空的风险。
- 依赖：`Controller` 通过 `Store.load()/save()` 读写；备份导出（v1/v2）读取 `state` 对象，格式不含存储位置信息，**不受本变更影响**。

## 方案（用户已确认 2026-09-21：「现在做」）

### 实体/字段/约束

| 存储 | 位置 | 键 | 值 | 说明 |
|---|---|---|---|---|
| 结构化数据 | IndexedDB `kylc-images` 库新增 `meta` store（版本 1→2） | `'state'` | 完整 state 对象（含 `_version`，结构与原 localStorage 存储一致） | 单一事实来源；容量受磁盘配额（estimate），不再受 5~10MB 限制 |
| 图片 | 不变（`images` store） | blobId / `t_`+blobId | Blob | 无变化 |
| `localStorage['kylc:data']` | 迁移完成后删除 | — | — | 消除双源歧义 |

不新增业务字段、不改备份格式（v1/v2 备份内容与导入路径完全不变）。

### 异步化改造

- IndexedDB 是异步 API，`Store` 新增 `init()`（异步加载 state 一次性完成）；`Controller` 新增 `init()`，`app.js` 在一切初始化前 `await`。
- `Store.save(data)` 改为**内存态立即更新引用 + IndexedDB 异步落库**（fire-and-forget，失败 Toast）。业务调用方（实测 22 处 `persist()`）签名不变，零改动。

### 迁移与回滚

- **自动迁移**：`init()` 时若 IDB `meta` 无 `state` 且 localStorage 有 `kylc:data` → 解析→`migrate()`→写入 IDB→成功后删除 localStorage 键。仅执行一次，无感。
- **回滚路径**：回退到旧版本代码前，先导出备份（v2 流式备份是跨版本安全网）；旧代码读不到 localStorage 会得到空数据，重新导入备份即可恢复。已写入 REQ 进度文档提示。
- **备份不变**：导出/导入对存储位置无感知，旧备份/新备份互通如前。

### 持久化申请

- `init()` 内 best-effort 调用 `navigator.storage.persist()`（Chrome 按站点活跃度自动批准或拒绝，无弹窗）；拒绝也不影响功能，仅保留回收风险提示义务（TECH 文档记录）。

### 数据生命周期

- state 生命周期同应用生命周期（增删改即时落库）；删除错题时只删图片 Blob，state 记录由业务删除逻辑处理（现状不变）。
- localStorage 遗留键 `BULK_GUIDE_KEY`（批量导入引导标记，wrongBook.js 独立使用）**不在迁移范围**，保持原样。

## 不做项

- 不做云同步/网盘集成（用户已有百度网盘会员，采用「备份文件存网盘同步目录」的零开发方案）。
- 不做多标签页跨页广播同步（IndexedDB 天然持久，同源多标签并发写为极低频场景，维持现状）。
- 不做 localStorage 写透镜像（避免配额问题复现）。

## 验收标准

1. 旧数据自动迁移：有 localStorage 旧数据的浏览器打开 → 数据完整出现在应用中，localStorage 键被删除，IDB `meta.state` 存在。
2. 持久化：改动数据 → 刷新页面 → 改动仍在（IDB 读取路径）。
3. **配额证明**：写入 >10MB 的 state（旧方案必失败量级）→ 保存成功且刷新后仍在。
4. 备份回归：v2 流式导出/导入、v1 导入在新存储层下行为不变。
5. 全新环境（无任何旧数据）首开不报错，得到默认数据。
6. `node --check` 与既有单测（qmark/export-json/export-ndjson）不回归。
