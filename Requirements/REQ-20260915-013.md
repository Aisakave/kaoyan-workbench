# 需求 REQ-20260915-013 错题本批量导入（本地图片文件夹）

> 分类：功能需求 · 影响范围：js/views/wrongBook.js + js/ui.js + css/components.css
> 状态：待用户实测 · 最后更新：2026-09-16

## 一、背景与目标

用户整理了 8 个文件夹（`C:\Users\Remilia\Pictures\错题\习题1~习题8`），每个文件夹内是按时间排序的「题目图 + 答案解析图」成对图片。目标：把图片批量导入应用「错题本」，生成错题记录，之后可再编辑补填文字栏。

现状约束（调研确认）：

| 约束点 | 说明 |
|---|---|
| 数据存储位置 | 错题文字存 localStorage，图片存 IndexedDB（浏览器内），**磁盘图片无法绕过应用直接写入**，必须经由应用内新入口 |
| 现有「导入备份」 | 是整体覆盖（`Controller.replace`），直接用来导图片会清空现有错题，不可复用 |
| 图片内容 | 手写数学题，无法自动 OCR，文字栏（我错在哪/关键一步）导入后为空，由用户之后编辑补填 |
| 现有上传能力 | `UI.pickImages` 仅支持单/多选文件，不支持选文件夹；存原图 + 自动生成缩略图 |

## 二、口径（用户本次明确确认）

用户选定方案：错题本新增「批量导入」入口，选文件夹 → 自动按时间配对 → 预览确认 → 写入。

| 决策点 | 结论 |
|---|---|
| 配对方式 | 图片按文件修改时间升序，两两配对：`(1,2)(3,4)…`，每对 = 1 条错题，含题目图+答案图 2 张 |
| 单数尾图 | 最后一张单独成 1 条（仅 1 图），不丢数据、不并入上一对 |
| 预览确认 | **要**。导入前弹窗逐条预览（图片缩略、科目、标题），确认后才写入；预览阶段不落任何数据 |
| 默认科目 | 数学（每条可在预览中单独改） |
| 默认标题 | 「习题N」（取文件夹名，如 习题1；每条可在预览中单独改） |
| 我错在哪 | 默认选「其他」，自定义原因留空（之后编辑补填） |
| 关键一步 | 留空（用户暂不填，之后编辑补填） |
| 数据安全性 | 只**新增**错题记录，绝不覆盖/清空既有数据 |
| 时间还原 | 错题 `created` 取该对「题目图」的文件修改时间，使「按添加时间」排序能还原文件夹内的原始先后顺序 |

## 三、技术方案

### 3.1 入口与选图

- 错题簿「全部错题」Tab 顶部按钮区：`收录错题` 旁新增 `批量导入` 按钮（图标+文案）。
- 点击后弹出 `<input type="file" webkitdirectory accept="image/*">` 选文件夹（Chrome/Edge 桌面端支持；手机端降级为多选图片）。
- 仅接受图片文件（`type.startsWith('image/')`），过滤非图片；超过 12MB 的图片跳过并提示（与现有上传一致）。

### 3.2 配对与预览

1. 文件按 `lastModified` 升序排序。
2. 两两配对 `(0,1)(2,3)…`；若单数，最后一张单独成 1 条。
3. 预览弹窗逐条展示：
   - 序号 + 张数标记（「题目+答案」或「仅题目」）；
   - 图片预览（`URL.createObjectURL` 临时预览，不写 IndexedDB）；
   - 科目下拉（默认数学，可改）；
   - 标题输入框（默认「习题N」，可改，空则显示「（未填知识点）」占位逻辑沿用现有）；
   - 每条可移除（删除该条，不导入）；
   - 底部汇总：「共 N 条，确认导入」/「取消」。
4. 导入过程中按钮显示进度（如「导入中 i/N」），完成后 Toast 提示结果。

### 3.3 写入

确认后逐条执行：

1. 对每条图片依次 `Store.saveImage` + `makeThumb` + `Store.saveThumb`（复用现有缩略图链路，图片存储与列表加载行为与手工上传完全一致）；
2. `Controller.addWrongQuestion({ subject, title, errorTypes:['other'], customError:'', keyStep:'', images:[...], created: 题目图 lastModified, updated: 题目图 lastModified })`；
3. 全部完成后 `render()` 刷新列表，Toast 显示「已导入 N 条错题」。
