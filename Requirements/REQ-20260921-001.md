# REQ-20260921-001 大容量流式备份（导出/导入）

## 背景

- 用户当前 100 道错题，备份文件已达 123MB（图片 base64 膨胀 ×1.33 后）。按此推算：1000 题 ≈1.2GB、3000 题 ≈3.7GB、5000 题 ≈6GB。
- 现有备份方案（单根 JSON + blob 下载/上传，含 BUG-20260921-001 修复后的分段拼装）存在两道浏览器硬上限：
  1. **导出**：全部图片 base64 字符串攒在 JS 堆里再拼文件，峰值内存约为备份体积 2 倍以上，Chrome 桌面单标签页堆上限约 4GB → 约千题量级崩标签页；
  2. **导入**：整个文件读成一根字符串再 `JSON.parse`，V8 单字符串上限约 1GB → 超限直接崩。
- 手机端（无 File System Access API + 标签页内存 200~400MB）已由用户明确放弃备份职能；几百题量级的手机分片方案本次不做。

## 目标

电脑端（Chrome/Edge）在**几千道错题、数 GB 备份**量级下，导出与导入全程稳定，内存占用与数据总量无关（恒定在单张图级别）。

## 用户确认口径（2026-09-21）

| 事项 | 结论 |
|---|---|
| 方案 | A：流式备份（NDJSON + File System Access API） |
| 电脑浏览器 | Chrome / Edge（支持写盘能力，方案完整可用） |
| 记住备份位置一键备份 | **不做**，每次弹「另存为」手选 |
| 图片压缩 | **不做**（用户要求字节级无损，清晰度不降） |
| 手机端大备份 | **不做**（硬件天花板；手机走降级路径，几百题内可用） |
| 云同步 | 不在本需求范围 |

## 备份格式设计（v2，NDJSON / JSON Lines）

文件扩展名 `.jsonl`，UTF-8，每行一个独立 JSON 对象，行间以 `\n` 分隔：

```
第 1 行（meta）：{"v":2,"createdAt":<ms>,"imagesTotal":<n>,"data":{…state 整包…}}
第 2..N+1 行（每张原图一行）：{"i":"<blobId>","d":"data:image/jpeg;base64,…"}
```

- `imagesTotal` 供导入侧计算确定进度。
- 与 v1（单根 JSON `{backup:true,createdAt,data,images}`）**不互通但可导入**：导入侧自动识别。
- state（localStorage 数据）不含图片本体，体积小（MB 级），meta 行整体序列化无内存风险。

## 兼容与降级

| 场景 | 行为 |
|---|---|
| Chrome/Edge 桌面导出 | `showSaveFilePicker` 选位置 → 流式写盘（内存峰值≈单张图） |
| Chrome/Edge 桌面导入 | 流式逐行读（`file.stream()` + TextDecoder）→ 逐张写 IndexedDB |
| 旧 v1 备份（.json）导入 | 自动识别整包格式，走原内存解析路径（≤~800MB 桌面安全，用户现存 123MB OK） |
| Firefox / Safari / 手机端 | 导出降级为现有 blob 分段下载（小数据量可用），导入降级为 readAsText 整包解析；导出时 toast 提示建议使用 Chrome/Edge |

## 改动范围

| 文件 | 改动 |
|---|---|
| `js/controller.js` | `exportAll()`：FSA 可用时流式 NDJSON 写盘（getAllKeys 逐张 get，不再 allImages 全量拉内存）；不可用时保留现有 blob 路径。`importAll()`：接收 File，流式逐行解析 v2 / 兼容 v1 整包 |
| `js/app.js` | 导入入口改为传 File 对象（原 FileReader 读文本前置） |

不改动：备份内容语义（仍是 全部数据 + 全部原图、跳过缩略图）、导入后逐张重建缩略图、文件命名日期戳（`backup-YYYY-MM-DD.jsonl`）、UI 入口与进度弹窗交互。

## 验收标准

1. **字节级无损**：导出备份中每张图的字节与 IndexedDB 原图完全一致（清晰度零损失）。
2. **内存平稳**：导出/导入过程 JS 堆占用与图片总量无关（验证方式：大批量模拟 + 单元等价测试）。
3. **v2 导入还原**：NDJSON 备份导入后 state 与全部原图完整恢复、缩略图重建。
4. **v1 兼容**：现有 123MB 旧格式备份可正常导入。
5. **降级可用**：无 FSA 环境走原路径不报错，并出现浏览器建议提示。
6. 进度显示正常（导出 x/y、导入 x/y，meta 行含 imagesTotal）。
