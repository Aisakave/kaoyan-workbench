# [BUG] 桌面端汉堡菜单按钮未隐藏

> 编号：BUG-20260915-003-桌面端汉堡按钮未隐藏
> 关联：REQ-20260915-011（验证中发现，用户确认修复）
> 状态：已修复
> 创建：2026-09-15
> 更新：2026-09-15

## 现象描述

桌面端（≥1024px）顶栏左上角的汉堡菜单按钮本应隐藏，却始终可见；点击它会打开手机式侧栏抽屉（给 `#sidebar` 加 `open` class），并触发全屏黑色蒙层，干扰桌面正常使用。

## 复现步骤

1. 以 ≥1024px 宽度打开应用
2. 观察顶栏左侧：汉堡按钮可见（应隐藏）
3. 点击该按钮 → 侧栏加 `open`、出现全屏黑蒙层（`.sidebar.open + .sidebar-mask` 不受宽度限制）

## 影响范围

仅桌面端顶栏按钮显隐与误触；无数据影响；手机端不受影响。

## 根因分析

`css/layout.css` 的 `.sidebar-toggle { display: none; }` 与 `css/components.css` 的 `.btn { display: inline-flex; }` 同为类选择器（优先级 0-1-0），而 components.css 在 index.html 中后加载，级联上后者胜出 → 隐藏规则失效。

`git show HEAD:` 证实上个提交即如此：该问题自 REQ-008 为 `.btn` 基类设置 `display: inline-flex` 起就存在，历次桌面实测均未检查此项，故未被发现。非 REQ-011 改动引入。

## 修复方案

两条规则改用 ID 选择器（优先级 1-0-0 > 0-1-0，不受加载顺序影响）：

- `css/layout.css`：`#btnToggleSide { display: none; }`（基础）
- `@media (max-width: 1023px)` 内：`#btnToggleSide { display: inline-flex; }`

## 验证结果

- Edge 真实视口 1280x800：`getComputedStyle(#btnToggleSide).display` = `none`（按钮隐藏）；点击主区空白无蒙层、侧栏无 `open`；路由切换正常。
- headless 双视口探针（iframe 模拟 390px / 1280px）：手机端媒体规则命中、按钮可见（计算值 `flex`，系 topbar flex 容器对子项 inline-flex 的正常块化，非异常）；桌面端 `none`。
- 全部匹配规则枚举确认：该按钮仅受上述 3 条 display 声明影响，无其它覆盖源。
- 手机 390px 交互（汉堡开 → 蒙层关）此前已在 REQ-011 验证中通过，本次未改动相关 JS。
- console 零报错。
