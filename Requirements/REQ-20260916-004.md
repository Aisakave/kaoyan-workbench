# REQ-20260916-004 导出/导入备份增加进度显示

- 日期：2026-09-16
- 分类：体验优化
- 状态：已完成
- 来源：用户反馈「导出数据和导入备份没有进度显示，用户不知道有没有成功」

## 确认口径

- 导出、导入全程用统一「进度弹窗」反馈：标题 + 阶段文字 + 进度条 + 百分比；弹窗锁定不可误关，任务结束（含失败）自动关闭，随后按原逻辑出 Toast。
- 导出阶段：读取图片 x/y（按图片数计百分比，占 0~85%）→「正在生成备份文件…」（JSON 序列化为同步大计算，无法计百分比，用不定进度动画）→ 完成。
- 导入阶段：「正在解析备份文件…」（JSON.parse 同步，不定进度）→「正在恢复图片 x/y」（0~90%）→「正在写入数据…」→ Toast「导入成功」。
- 不做项：不做可取消/暂停；不改导出导入的数据格式与兼容性逻辑；不改失败提示文案（新增导出失败兜底提示除外）。
- 数据影响：无（不新增字段、不迁移、不改存储结构）。

## 实现摘要

| 改动 | 文件 | 说明 |
|---|---|---|
| 进度弹窗组件 | `js/ui.js` | 新增 `UI.progressModal(title)`：locked 弹窗，返回 `update(pct,msg)` / `indet(msg)` / `close()`；确认弹窗文案结构复用 modalShell |
| 不定进度动画 | `css/components.css` | `.progress.indet > i` 滑块循环动画（34% 宽滑过轨道），复用既有 `.progress` 轨道样式 |
| 导出接入 | `js/controller.js` `exportAll` | try/finally 保证失败也关弹窗；`nextFrame()` 在 JSON.stringify 前让浏览器先绘制进度文字 |
| 导入接入 | `js/controller.js` `importAll` | 弹窗在解析前打开；恢复图片循环逐张更新百分比；失败路径关弹窗 + 原有错误 Toast |

## 验证证据（2026-09-16，Chromium headless 实测）

- `node --check` ui.js / controller.js 通过。
- 导出：播种 40 张测试图后点击「导出数据」，采样确认弹窗打开 →「正在生成备份文件…」→ 自动关闭；空库与有图库均正常完成。
- 导入：800 张图测试备份经 `#fileImport` 上传，采样确认「正在恢复图片 1/800 → 790/800」百分比 0%→89% 平滑推进 →「正在写入数据…」→ 弹窗关闭。
- 导入后数据替换验证：任务列表仅剩备份内标记任务「导入链路验证」，路由自动跳回首页。
